# The Marine Chronometer

Two browser-based projects about the marine chronometer, centred on the
Hamilton Model 21: a two-day fusee chronometer with a spring detent escapement,
made for the U.S. Navy from 1941.

Orel Magidish (assisted by Claude Opus 5.5) – September 2026

| File | What it is |
|---|---|
| [`chronometer-working-model.html`](chronometer-working-model.html) | **The main project.** An interactive 3D model of the Model 21 running in real time inside its gimballed case and mounting box, with an eight-step walkthrough, cross-sections and part descriptions with Hamilton part numbers |
| [`marine-chronometer.html`](marine-chronometer.html) | A long-form interactive essay covering longitude, the balance, the helical spring, temperature compensation, the fusee, the train, the detent escapement and the gimbals |

Each is a single self-contained HTML file: download it and open it in any modern
browser. It works offline and needs no server. three.js and the fonts are built
into the file.

## Setting up

You need:

- **Git**, to clone the repository.
- **Python 3.9 or later**, for the build. It uses only the standard library.
- **A browser.** Any current Chrome, Edge, Firefox or Safari works.

Clone and build:

    git clone git@github.com:OrelMag/marine-chronometer-model.git
    cd marine-chronometer-model
    python build.py

On macOS and Linux, use `python3` wherever these instructions say `python`.

The verification tools (optional, only needed when you change the model's
geometry) need three Python packages and a browser that Playwright drives:

    python -m pip install numpy scipy playwright
    python -m playwright install chromium

## Building

    python build.py

This one command:

1. Builds the model into `marine-chronometer-source/chronometer-working-model/dist/chronometer-working-model.html`.
2. Builds the essay into `marine-chronometer-source/marine-chronometer-essay/marine-chronometer.html`.
3. Copies both to the repository root.
4. Assembles `site/`, the folder you upload to a web host:
   - `index.html` is the model, so the site opens straight into it;
   - `marine-chronometer.html` is the essay;
   - `social.png` and `social-movement.png` are the link-preview images: the dial in its box for the model page, the mechanism for the essay page (both also work for posting);
   - `_headers` holds security and caching headers, read by Cloudflare Pages and Netlify.

The build fails if a page still loads a script, stylesheet or font from another
server. That keeps the published files working offline and in countries where
common CDNs are blocked.

Once you know the site's address, pass it in. The pages then show a picture when
the link is shared, and search engines see the canonical address:

    python build.py --site-url https://marine-chronometer.pages.dev

Page addresses are written without `.html` (`/marine-chronometer`), because
Cloudflare redirects `/marine-chronometer.html` there. On a host that serves the
`.html` address directly (Netlify, GitHub Pages, most plain web servers), add
`--keep-html`.

Rebuild after every change and commit the regenerated root copies with your
source changes, so that the two stay identical.

## Changing things

### The model

Work on the unbuilt source, which loads the files directly, so a browser reload
shows each edit:

1. Open `marine-chronometer-source/chronometer-working-model/index.html` in a
   browser (double-clicking it works).
2. Edit the files in `css/` and `js/`, then reload the page.
3. Keep the browser's developer console open (F12). Errors appear there, and so
   do warnings from the geometry builders, for example a hole that crosses a
   plate's outline.
4. When it looks right, run `python build.py` from the repository root.

Useful URL flags:

- `?snap` turns off camera and state easing, so views settle at once.
- `?qa` exposes the movement and camera helpers to the verification tools.

For example: `index.html?snap&qa`.

If the page is opened from a local web server instead of the file, start one at
the repository root. The page reads `../../vendor/`, so the server must be able
to reach it:

    python -m http.server 8000
    # then open http://localhost:8000/marine-chronometer-source/chronometer-working-model/

The model's own [README](marine-chronometer-source/chronometer-working-model/README.md)
explains how the code is organised. Its "Modifying the model" section walks
through common changes: a part's shape, a new part, gear ratios, the dial, the
walkthrough, views and materials.

The essay's detent figure uses a copy of the model's escapement solver (`ESC`
in `js/movement.js`). If you change `ESC`, copy it into
`marine-chronometer-essay/src/p4.js` as well; the essay's
[README](marine-chronometer-source/marine-chronometer-essay/README.md) says
what differs.

### The essay

The essay is one page split into four pieces in
`marine-chronometer-source/marine-chronometer-essay/src/`. `p1.html` holds the
markup, styles and prose and opens a `<script>` tag that `p2.js` to `p4.js`
continue, so none of the pieces works on its own. Edit them, then run
`python build.py` and open the rebuilt `marine-chronometer.html`.

## Checking your changes

Before committing a change to the model:

1. **Past fixes.** Look up the part, control or build step in
   [RESOLVED.md](RESOLVED.md), so an old bug doesn't come back.
2. **Build.** `python build.py` at the root must finish without errors.
3. **Console.** Open the rebuilt `chronometer-working-model.html`, click through
   every view and the walkthrough, and check the console has no errors or
   warnings.
4. **Geometry** (if you changed any part), run from
   `marine-chronometer-source/chronometer-working-model/tools/`:

       python dyn.py        # collisions through a full escapement cycle
       python fine.py       # the same at 0.05 mm, round the train and over the wind, plus the barrel's margins (exit code 1 on anything new)
       python views.py before   # (before the change) renders every view; after it: python views.py after, then python views.py --diff before after
       python audit.py      # screws, pivots, loose parts in the movement
       python audit.py box  # the same for the box and gimbals
       python p3fit.py      # render from the top-view photograph's camera (writes r_p3.png; compare with ../verification/topview-comparison.png)
       node escapement.js   # the escapement's lock, let-off, overall, drop and clearances (Node.js only)

   `dyn.py` should list only intended joints: pivots in their jewels, collets
   on arbors, hands on their staffs. `fine.py` should print `ok` on every line;
   its table `EXPECTED` gives the reason for each intended contact. The
   `views.py` diff should show changed pixels only on the parts you changed. `audit.py` is expected to report the
   winding-stop pin and the free ends of the balance screws and the timing
   weights' screws; most of its
   coplanar-face hits are faces in contact. `escapement.js` marks each figure
   `ok` or not against the manual's value. The tools write their output files
   into the folder they're run from.
5. **Preview images.** If the model's appearance changed, re-render them:
   `python social.py` (from the same `tools/` folder), then rebuild.
6. **Record fixes.** If the change fixes a bug, add it to
   [RESOLVED.md](RESOLVED.md) under the right heading, with the commit hash.
7. **Commit** the source and the regenerated root copies together.

## Publishing the website

The website is a folder of static files (`site/`): no server code, no
database. Any static host can serve it. The files are self-contained, so a
visitor's browser fetches only these few files, from the host alone.

### The live site

The site is live at https://marinechronometer.orelmac.workers.dev, a
Cloudflare Worker that serves `site/` as static files. `wrangler.jsonc` at the
root describes it. To update it (Node.js provides `npx`; the first run opens a
browser window to log in to Cloudflare):

    python build.py --site-url https://marinechronometer.orelmac.workers.dev
    npx wrangler deploy

Pushing to GitHub doesn't deploy it. The steps below are for setting up a new
site elsewhere.

### Recommended: Cloudflare Pages

It's free, has unlimited bandwidth on the free plan, serves from hundreds of
cities worldwide, and works with a private GitHub repository. Cloudflare
occasionally renames dashboard items; the steps below describe what to look for.

**First upload (about ten minutes):**

1. Create a free account at https://dash.cloudflare.com/sign-up.
2. Choose a project name, for example `marine-chronometer`. The site's address
   will be `https://marine-chronometer.pages.dev` (if the name is taken, pick
   another and use it in the next step).
3. Build with that address:

       python build.py --site-url https://marine-chronometer.pages.dev

4. In the dashboard, open **Workers & Pages**, choose **Create**, then the
   **Pages** tab, then **Upload assets** (Direct Upload). If you're offered a
   Worker first, look for the Pages option.
5. Enter the project name from step 2 and create the project.
6. Drag the **`site` folder** (the folder itself, not the files inside it, and
   not the whole repository) onto the upload area, and click **Deploy site**.
7. Open `https://marine-chronometer.pages.dev`. The model loads as the home
   page, and the essay is at `/marine-chronometer.html`.

**Later updates:** rebuild with the same `--site-url`, open the project in the
dashboard, choose **Create deployment**, and drag `site/` in again. Each
deployment is kept, so you can roll back from the project's Deployments list.

**Updating from the command line instead** (needs Node.js, which provides
`npx`):

    python build.py --site-url https://marine-chronometer.pages.dev
    npx wrangler pages deploy site --project-name marine-chronometer

The first run opens a browser window to log in to Cloudflare.

**Automatic deploys on every push (optional):**
1. In the project, choose to connect it to GitHub and authorise access to the
   repository.
2. Set the build command to
   `python build.py --site-url https://marine-chronometer.pages.dev`.
3. Set the build output directory to `site`.

If the build log says Python can't be found, add an environment variable
`PYTHON_VERSION` with the value `3.11`.

**Your own domain (optional):** buy one (Cloudflare Registrar sells them at
cost, from about US$10 a year), then add it under the project's **Custom
domains**. Rebuild with `--site-url https://your-domain` and upload again, so
link previews use the new address.

**Check the link preview:** paste the address into https://www.opengraph.xyz.
The model page should show the dial picture, the essay page the mechanism, each with its title and description.

### Alternatives

- **Netlify Drop:** open https://app.netlify.com/drop and drag the `site`
  folder onto the page. You get an address immediately; create a free account
  to keep it and to rename it (`https://<name>.netlify.app`). Then rebuild with
  that `--site-url` and drag the folder in again. The free plan includes
  100 GB of traffic a month.
- **GitHub Pages:** free only for public repositories (this one is private).
  If you make it public:
  1. Commit a copy of `site/` in a `docs/` folder.
  2. Under **Settings → Pages**, choose **Deploy from a branch**, then `main`,
     then `/docs`.
  3. The address will be `https://orelmag.github.io/marine-chronometer-model/`.
- **Anywhere else:** upload the contents of `site/` to the web root of any
  hosting that serves plain files, such as a university or museum web server,
  or Amazon S3 with CloudFront.

The single `chronometer-working-model.html` file also works on its own. You can
email it, put it on a USB stick or attach it to a course page; it runs from the
file with no connection.
